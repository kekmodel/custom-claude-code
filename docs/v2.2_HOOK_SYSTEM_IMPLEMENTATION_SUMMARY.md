# v2.2 Hook System Implementation Summary

## 개요

v2.2는 Claude Agent SDK의 Hook System을 LangGraph 기반 구현에 완전히 통합한 버전입니다. 이전 버전에서는 Hook System의 구조만 있었지만, 실제로 호출되지 않았습니다. 이번 구현으로 4가지 Hook 이벤트가 모두 작동합니다.

## 구현된 Hook Events

### 1. PreToolUse Hook
**위치**: `graph.py:execute_tools()`
**기능**: 도구 실행 전에 검증, 차단, 입력 수정
**통합 상태**: ✅ 완료

**핵심 기능**:
- `decision="block"` → 도구 실행 차단
- `updatedInput` → 도구 입력 파라미터 수정
- `systemMessage` → LLM에게 피드백 전달

**코드 예시**:
```python
# PreToolUse Hook 트리거
pre_hook_result = await trigger_hook(
    event="PreToolUse",
    input_data={
        "tool_name": tool_name,
        "tool_input": tool_args,
    },
    tool_use_id=tool_call_id,
    context=context
)

# Hook이 차단하면 실행 안 함
if pre_hook_result.get("decision") == "block":
    error_msg = pre_hook_result.get("systemMessage", "Tool execution blocked by hook")
    tool_messages.append(
        ToolMessage(content=f"[BLOCKED] {error_msg}", tool_call_id=tool_call_id, name=tool_name)
    )
    # systemMessage를 LLM에게 전달
    if pre_hook_result.get("systemMessage"):
        tool_messages.append(
            HumanMessage(content=f"<system-reminder>\n{pre_hook_result['systemMessage']}\n</system-reminder>")
        )
    continue
```

### 2. PostToolUse Hook
**위치**: `graph.py:execute_tools()`
**기능**: 도구 실행 후 결과 후처리, 즉시 중단
**통합 상태**: ✅ 완료

**핵심 기능**:
- `continue_=False` → 즉시 실행 중단 (다른 모든 도구 실행 스킵)
- `additionalContext` → LLM에게 추가 컨텍스트 전달
- `stopReason` → 중단 이유 명시

**코드 예시**:
```python
# PostToolUse Hook 트리거
post_hook_result = await trigger_hook(
    event="PostToolUse",
    input_data={
        "tool_name": tool_name,
        "tool_input": tool_args,
        "tool_response": result,
    },
    tool_use_id=tool_call_id,
    context=context
)

# continue_ 필드 체크 (즉시 중단)
if not post_hook_result.get("continue_", True):
    stop_reason = post_hook_result.get("stopReason", "Execution halted by hook")
    tool_messages.append(
        ToolMessage(content=f"[STOPPED] {stop_reason}", tool_call_id=tool_call_id, name=tool_name)
    )
    # 즉시 반환 (더 이상 도구 실행 안 함)
    return {"messages": tool_messages, "todos": updated_todos}
```

### 3. UserPromptSubmit Hook
**위치**: `main.py:run_conversation_loop()`
**기능**: 사용자 입력 제출 시 컨텍스트 자동 주입
**통합 상태**: ✅ 완료

**핵심 기능**:
- `additionalContext` → 사용자 입력에 자동으로 컨텍스트 추가
- 테스트 모드, 디버그 정보, 환경 설정 등을 투명하게 주입 가능

**코드 예시**:
```python
# UserPromptSubmit Hook 트리거
hook_result = await trigger_hook(
    event="UserPromptSubmit",
    input_data={"user_input": user_input},
    tool_use_id=None,
    context=context
)

# additionalContext를 user_input에 추가
final_input = user_input
hook_output = hook_result.get("hookSpecificOutput", {})
if hook_output.get("additionalContext"):
    additional = hook_output["additionalContext"]
    final_input = f"{user_input}\n\n<system-reminder>\n{additional}\n</system-reminder>"

messages.append(HumanMessage(content=final_input))
```

### 4. SubagentStop Hook
**위치**: `nodes.py:execute_subagent()`
**기능**: Subagent 완료 시 결과 후처리
**통합 상태**: ✅ 완료

**핵심 기능**:
- `modifiedResult` → Subagent 결과 수정
- `additionalContext` → Subagent 실행 요약 추가
- 메시지 수, 실행 시간 등 메타데이터 자동 추가 가능

**코드 예시**:
```python
# SubagentStop Hook 트리거
hook_result = await trigger_hook(
    event="SubagentStop",
    input_data={
        "subagent_type": subagent_type,
        "prompt": prompt,
        "result": result_content,
        "message_count": len(final_state["messages"]),
    },
    tool_use_id=None,
    context=context
)

# Hook이 결과를 수정했으면 반영
if hook_result.get("modifiedResult"):
    result_content = hook_result["modifiedResult"]

# additionalContext를 결과에 추가
hook_output = hook_result.get("hookSpecificOutput", {})
if hook_output.get("additionalContext"):
    additional = hook_output["additionalContext"]
    result_content = f"{result_content}\n\n<hook-note>\n{additional}\n</hook-note>"
```

## 핵심 수정 사항

### 1. hooks.py:trigger() 함수 수정
**문제**: `hookSpecificOutput`을 수집만 하고 반환하지 않음
**해결**: `accumulated_result`를 사용하여 모든 hook 출력 누적 후 반환

**변경 전**:
```python
# Hook별 특수 출력 처리
if 'hookSpecificOutput' in result:
    hook_output = result['hookSpecificOutput']
    if isinstance(hook_output, dict):
        input_data.setdefault('_hook_outputs', []).append(hook_output)

return {}  # 모든 hook 통과
```

**변경 후**:
```python
# 결과 누적을 위한 변수
accumulated_result = {}

# ... hook 실행 루프 ...

# Hook별 특수 출력 처리
if 'hookSpecificOutput' in result:
    hook_output = result['hookSpecificOutput']
    if isinstance(hook_output, dict):
        input_data.setdefault('_hook_outputs', []).append(hook_output)
        # 최종 결과에도 포함 (마지막 hook의 것이 우선)
        accumulated_result['hookSpecificOutput'] = hook_output

return accumulated_result  # 모든 hook 통과, 누적된 결과 반환
```

### 2. graph.py:execute_tools() 수정
**추가된 기능**:
- HookContext 생성 (session_id, turn_count)
- PreToolUse Hook 호출 및 blocking 처리
- PostToolUse Hook 호출 및 continue_ 처리
- systemMessage를 LLM에게 HumanMessage로 전달
- additionalContext를 LLM에게 전달

### 3. nodes.py:execute_subagent() 수정
**추가된 기능**:
- SubagentStop Hook 트리거
- modifiedResult 반영
- additionalContext를 `<hook-note>` 태그로 결과에 추가

### 4. main.py:run_conversation_loop() 수정
**추가된 기능**:
- UserPromptSubmit Hook 트리거
- additionalContext를 user_input에 자동 추가

## 실사용 예시

### 예시 1: 위험한 Bash 명령어 차단

```python
async def bash_safety_hook(input_data, tool_use_id, context):
    """PreToolUse: 위험한 bash 명령어 차단"""
    if input_data.get("tool_name") == "run_bash":
        command = input_data.get("tool_input", {}).get("command", "")

        dangerous_patterns = ["rm -rf /", ":(){ :|:& };:", "mkfs", "dd if="]
        for pattern in dangerous_patterns:
            if pattern in command:
                return {
                    "decision": "block",
                    "systemMessage": f"🚫 Dangerous command blocked: {pattern}",
                    "hookSpecificOutput": {
                        "hookEventName": "PreToolUse",
                        "permissionDecision": "deny",
                        "reason": f"Command contains dangerous pattern: {pattern}"
                    }
                }
    return {}

register_hook("PreToolUse", bash_safety_hook, matcher="run_bash")
```

### 예시 2: Critical 에러 자동 중단

```python
async def critical_error_handler(input_data, tool_use_id, context):
    """PostToolUse: Critical 에러 감지 시 즉시 중단"""
    tool_response = str(input_data.get("tool_response", ""))

    if any(keyword in tool_response.upper() for keyword in ["CRITICAL", "FATAL", "SEGFAULT"]):
        return {
            "continue_": False,
            "stopReason": "Critical error detected in tool output",
            "systemMessage": "🚨 Execution stopped due to critical error. Please review the error and fix before continuing.",
            "hookSpecificOutput": {
                "hookEventName": "PostToolUse",
                "errorType": "critical",
                "recommendation": "Review error logs and restart agent"
            }
        }

    return {"continue_": True}

register_hook("PostToolUse", critical_error_handler)
```

### 예시 3: Subagent 실행 통계 자동 추가

```python
async def subagent_stats_hook(input_data, tool_use_id, context):
    """SubagentStop: Subagent 실행 통계 자동 추가"""
    subagent_type = input_data.get("subagent_type")
    message_count = input_data.get("message_count", 0)
    prompt = input_data.get("prompt", "")

    # 통계 계산
    prompt_length = len(prompt)
    avg_msg_length = len(input_data.get("result", "")) / max(message_count, 1)

    return {
        "hookSpecificOutput": {
            "hookEventName": "SubagentStop",
            "additionalContext": f"""
<Subagent Execution Summary>
- Type: {subagent_type}
- Messages: {message_count}
- Prompt Length: {prompt_length} chars
- Avg Message Length: {avg_msg_length:.1f} chars
- Status: ✅ Completed
</Subagent Execution Summary>
            """
        }
    }

register_hook("SubagentStop", subagent_stats_hook)
```

### 예시 4: 디버그 모드 자동 컨텍스트 주입

```python
DEBUG_MODE = True

async def debug_context_injector(input_data, tool_use_id, context):
    """UserPromptSubmit: 디버그 모드일 때 추가 컨텍스트 주입"""

```

## 핵심 장점

### 1. 확장 가능성 (Extensibility)
- 코드 수정 없이 새로운 동작 추가 가능
- Hook 등록만으로 기능 확장

### 2. 안전성 (Safety)
- 위험한 명령어 실행 전 차단
- Critical 에러 감지 시 즉시 중단

### 3. 투명성 (Transparency)
- systemMessage를 통해 LLM에게 Hook 동작 설명
- additionalContext로 추가 정보 제공

### 4. 유연성 (Flexibility)
- Matcher 패턴으로 특정 도구에만 Hook 적용
- 다중 Hook 체이닝 가능

## 향후 개선 방향

### 1. Pre-Compact Hook (낮은 우선순위)
- 메시지 압축 전에 중요 메시지 보호
- 현재는 미구현 (v2.1에서 압축 로직 있음)

### 2. Stop Hook (낮은 우선순위)
- Agent 실행 완전 중지 시 정리 작업
- 현재는 미구현

### 3. Hook 성능 모니터링
- Hook 실행 시간 측정
- 느린 Hook 감지 및 경고

### 4. Hook 에러 핸들링 개선
- Hook 실행 실패 시 fallback 전략
- Hook 에러 로깅 강화
